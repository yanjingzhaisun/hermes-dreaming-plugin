# dreaming v2 设计原则

## 四个目标

1. **无需用户裁定**：夜间全链路不等待用户回复。动作按策略路由自动处理；无法证明安全的动作 fail-closed，保留来源并记录内部 deferred。
2. **有效压缩 MEMORY.md / USER.md**：独立测量两文件水位，按安全顺序压缩、合并、验证承接后下沉；仅在仍超限且无安全候选时按公式提额。
3. **对话中纠错、当夜对齐**：捕获用户明确纠错，依据原始消息时间、来源与当前事实状态对账。仅同主体、主题、范围且可排序的明确偏好或工作惯例可走 recency-wins；身份、红线和证据不足均不自动落地。
4. **基于时间逐步调整**：仅在 recall telemetry 完整可信时执行数值衰减；按类别策略计算，不物理删除事实，不把衰减/召回冒充新证据。遥测缺失或损坏时衰减为零并保留来源事实。

后台 staged 改写审批是达成零裁定目标的一段执行机制：模型逐项判断，脚本应用或丢弃并留回执；授权仅覆盖 MEMORY/USER staged 写，不延伸到 fact_store 物理删除。

## 安全不变量

- **判断留模型层**：脚本不以关键词表替代语义判断；脚本执行确定性验证、路径处理、锁、写入与回执。
- **Fail-closed**：哈希变化、保护冲突、证据不足、目标状态漂移或 API 结果不明时不执行该动作，来源原样保留并记录 deferred。
- **保护集字节冻结**：保护块的完整 bytes 与相对顺序都必须保持。EXPECTED 是目标实例的权威集合，夜间流程不得修改它或刷新其哈希来掩盖漂移。
- **先承接后撤源**：移动或下沉内容前先备份、写目标并验证可读/可检索，再撤除来源。任何不确定结果保留原文。
- **逐笔可审计**：每项记录 run_id、动作 ID、来源与目标哈希、前后状态、工具结果和恢复状态。verified 只由真实 after-state 证据支持。
- **成功静默**：无需用户动作的成功运行不产生 stdout 或推送；失败告警只汇总可证实状态，不暴露记忆原文、路径或行动项。

## 夜间顺序

```text
start 回执 → 抽取/纠错捕获 → 纠错对账 → pending 审批
 → 记忆/技能/按需辅助整理 → MEMORY 与 USER 水位 → 保护集验收 → finish 回执
```

具体实例可按其有效工作流调整非依赖步骤，但纠错必须在水位瘦身前完成，受纠错影响的主题须重新读取当前版本。
